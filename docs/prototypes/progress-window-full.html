改造清单（对应 issue #81 四条 + #76 一条）

分类改了什么为什么
A图标 批处理行状态图标从 emoji（🔄 ✅ ❌ ⏳ ⏭）换成 PathIcon，走 AppIcons.axaml 并登记 IconTestViewModel 字体缺字时会渲染成残影 —— 截图里「压缩包列表项左侧图标显示不全」就是这个原因，不是布局问题
AToolTip 状态行右侧复制按钮补 ToolTip「复制状态文本」；错误摘要里的第二个复制按钮同样补上 全窗口唯一没有 ToolTip 的纯图标按钮（ProgressWindow.axaml:1246-1258）；SummaryCopyBtn 更是连提示都没有
A取消按钮 取消按钮改用 ThemeStatusErrorBrush 描边 + 文字，与暂停按钮区分 两者原本尺寸、底色、边框完全相同，破坏性操作没有任何视觉区分
A截断 文件名统一 MiddleEllipsis（原来是「简约用 Character、详细用 Middle」两套） 同一个窗口里两种截断规则，长文件名看起来像被随机切掉
B百分比 百分比只在底部合并行右侧出现一次；批处理行只在「多包」时保留自己的百分比 原来同一个 40% 出现 4 次（列表行 / 当前文件 / 卡片 / 两根大条）
B单包折叠 单包时「压缩包列表」表头隐藏、行内子摘要隐藏，整块压成一行 表头「压缩包列表」+ 行内「压缩包 1/1」是同一句话说了两遍
B三行合一 「并行 4 / 速度 / 压缩后 (28%)」+「31%」+「已用 / 剩余」合并成底部一行 三段信息各占一行，窗口白白高出 3 行
C视图切换 「简约 / 详细 / 列表」与「精简 / 标准 / 完整」两行两套，合并成一行五档（极简 / 标准 / 详细 / 完整 / 列表） 「简约」与「精简」两个近义词各表示一次「少」，用户无法区分；且「精简」档原本几乎不改变任何内容（IsMinimalDensity 只出现在它自己的 RadioButton 上）
C状态面板 信息区从 7 行压到 3 行（视图切换 1 行 + 统计卡 1 行 + 底部合并行 1 行） 见下方高度账
C卡片一行 卡 MinWidth 80→72、间距用 WrapPanel.ItemSpacing=SpacingXxs（2/4/6）+ LineSpacing、字号各降一档，800 宽一行排下；窄窗由 WrapPanel 自然换行 原来 9 × 80 + 8 × 24 = 912px > 800，靠「只显示有数据的卡」侥幸没暴露，一旦 ZIP 自适应全上报就被 ClipToBounds 硬切。
计划里原写的「WrapPanel 没有 Spacing」是错的 —— Avalonia 12 实测有 ItemSpacing / LineSpacing，可直接 {DynamicResource …}
D三项统计 「总大小」卡在压缩流程拆成「压缩前 / 压缩后 / 压缩率」三连卡；底部 🗜 那项同步删掉避免重复；7z / tar.gz 拿不到的数显「—」 来自 #76 图 4。数据都已有：TotalBytes、TotalCompressedBytes（仅 ZIP 上报）、OverallCompressionText
E底纹 信息区整块（.info，含内边距与边框）挂一层底纹进度：进行中按百分比截断、准备/扫描满宽淡黄、完成淡绿、失败淡红、取消淡灰、暂停降透明度。
挂整块还是只挂卡片行，用控制条「③ 底纹挂」现场对比		 替代完整档的独立总进度条 —— 那一根条只在完整档存在，切到别的档又冒出来，同一信息两套呈现
E列表过滤 列表档的统计卡行换成 5 张可点卡（已完成 / 跳过 / 出错 / 已覆盖 / 全部，全部在最右），尺寸与完整档完全一致；再点一次已选中的卡回到「全部」 过滤值与卡片上的数字同源，不用另起一套胶囊；三行同构卡与完整档切档不跳

这一版没解决的

① #76 三项统计与卡片宽度的冲突（唯一还没定的一条）：勾上 #76 后完整档变 11 张卡（解压流程再加「暂存」是 12 张），800 宽下按 72 卡宽 + 4 间距仍有 792px 与 872px，必然换行。真机要一行放下，要么把三张合成一张三行的「压缩前 / 后 / 率」，要么接受开启时换行。这一条是给 D 项拍板时看的，勾一下就能看到差距。
② 底纹在「不确定态」（准备 / 扫描）用满宽淡黄代替滚动动画，静止不动可能被误认为卡死，靠扫描计数兜底。
③ 5 档在 MinWidth=500 时仍是一行（实测约 402px vs 可用 468px，余 66px），但已经很紧；真机字号若比原型大一点就会溢出。
④ 批处理行百分比在单包时已隐藏，但多包时与底部百分比仍共存 —— 语义不同（单包 vs 总体），需要确认是否可接受。
⑤ 列表档的「已完成 / 跳过 / 出错 / 已覆盖 / 全部」五个数字需要给 ProgressViewModel 补一个带通知的已完成计数（_statsCompleted），否则最后一条永远少 1。
⑥ MaxSeedEntryCount = 5000：超过 5000 条的包一条行都不建，过滤与列表档都会是空的，这是既有上限，不在本次范围。
