决策逻辑（Spec §2）

// 优先级从高到低
1. options.ParallelExtractDegree > 0
   → 调用方指定（测试/特殊场景）
2. EnableParallelExtract = false
   → 返回 1（串行）
3. SmartParallelDegree = false
   → 手动值 > 0 ? 手动值 : ProcessorCount
4. Smart 开 且 ≥1GB 且 预测试开
   → ParallelDegreeOptimizer 快速测试
5. Smart 开（默认路径）
   → DiskTypeDetector
     SSD → SmartSsdDegree(12)
     HDD → SmartHddDegree(8)
     Unknown → min(CPU核数, 12)
上方 mockup 右下决策条即按此链实时推导；步骤灰=未命中，绿=命中。

大包预测试流程（Spec §4）

// 触发：size ≥ 1GB && LargeArchivePreTest
1. 取前 ~50MB 样本（≥5 条 ≤50 条）
2. 按核数选 4 个配置，逐个：
   16核 → [4, 8, 12, 16]
   8核  → [2, 4, 8, 8] 去重
3. 解压到目标目录 __parallel_test_{n}
   → 计时 → 立即删除
4. 取最快 → 正式解压
// 任一步失败/取消 → 回退磁盘类型默认值

与现状的关系（两处「并行线程数」入口）

1. 设置窗口（本原型） —— 全局默认：并行总开关 + 智能（SSD/HDD 双线程数）/ 手动单值。
2. 解压设置对话框（ExtractSettingsWindow.axaml:127-138）—— 既有的 NumericUpDown(1-16) + 硬编码提示「(1=串行，默认=CPU核心数)」。该对话框值经 ExtractSettingsViewModel 直接写入 ArchiveOptions，属单次解压覆盖， 优先级最高（决策链第 1 步），不受全局开关与智能模式影响。
⚠ 实施时需处理：解压对话框的提示文案在智能模式下会与新默认值矛盾 （显示「默认=CPU核心数」但实际默认已是 SSD=12）——计划中需同步改为动态提示或中性文案。

帮助弹窗（ParallelExtractHelpDialog）— 点 mockup 中 [?] 查看

三个 [?] 按钮打开同一个帮助弹窗，弹窗内三个章节分别对应（并行解压 / 智能并行度 / 大包预测试）； 弹窗为独立 Window（非内联 ToolTip），规避规则 14 中禁用控件 ToolTip 不弹的问题， 也与既有 LogPrivacyHelpDialog / 密码库帮助对话框风格一致。 文案 key：ParallelHelp_Title / ParallelHelp_EnableSection / ParallelHelp_SmartSection / ParallelHelp_PreTestSection（三语成对）。
原型还原设置卡片布局与决策逻辑（隐藏规则、预测试触发条件、帮助弹窗入口）， 卡片 1-4 为现状静态示意，颜色为原型暗色 house style，非 Avalonia 真实主题值。
