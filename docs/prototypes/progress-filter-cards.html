三个已确认的取舍

① 「全部」保留 —— 否则过滤到一个状态后没有「回到全部」的可见入口（只能再点同一张卡，不直观）。
② 卡片不再是胶囊形状 —— 胶囊的圆角会让它读起来像「标签」而不是「统计」，同构卡片才能做到「两档同一套视觉语言」。
③ 「已处理 742」不进列表档 —— 它含跳过和出错，语义与「已完成 1,233」重叠；列表档看逐条目时，具体多少由「全部 1,248」和底部百分比表达。

实现要点

点做法
XAML 结构 StatsCardsPanel（ProgressWindow.axaml:701-705）整块绑 IsVisible="{Binding IsFullDensity}"。 改成外层 Border 常驻 + 内部 IsDetailedOrFull / IsListMode 两套卡行。 两套必须共用同一套度量（MinWidth=72 + 三行 grid），否则切档会跳。
卡片模板复用 建议抽一个 DataTemplate / ControlTheme，两档只是 IsHitTestVisible 与 IsEnabled 不同，视觉三层结构完全一样。
已完成计数 新增 _statsCompleted + _statsCompletedBytes； AccumulateTerminalBytes 加 case Completed； UpdateEntryStatus 的守卫加 or EntryRowState.Completed； ActivateEntryByName 里补一处累加（它绕过 UpdateEntryStatus）。
过滤数据源 不动 _entryItems（ActivateEntryByName 还按 Name 全表匹配）， 另开 EntryViewItems 投影集合。Avalonia 12 没有 ICollectionView。
过滤时机 切卡全量算一次 + UpdateEntryStatus / ActivateEntryByName 里 State 变了单行增删。只认 State。
空状态 过滤后 0 条 → 「没有匹配的条目 + 显示全部」。现在没有，必须新增。
5000 条上限 软肋：MaxSeedEntryCount = 5000 是「超了就不建行」，超大包列表本来就是空的 ⇒ 过滤与卡片都无从谈起，需单独决策。
