观察 1状态行恒显示当前状态，与「完成/失败」无关；错误摘要隐藏（Rule 6）。位置：总进度信息区之下、按钮行之上。

观察 4 · 冗余点失败时两行同时出现：状态行给「结果概览」、错误摘要给「失败明细」。请判断此时状态行是否多余 / 信息是否重复 —— 这是 B 区别于 A 的唯一场景。
方案 B 定义：状态行（①）与错误摘要（②）两条并存，均位于总进度信息区与按钮行之间；两行都可复制（文本可选中 + 各自 ⧉ 复制按钮 + toast），状态行恒显示，错误摘要仅有错误时出现。
字号：状态行 14px SemiBold（比既有 12px 状态文字加大一档），错误摘要维持 12px（明细性质，视觉层级低于状态行）。
对应当前实现：① = Row 3 StatusMessage（下移 + 改可复制 + 字号加大，7 行布局不变，仅行序调整）；② = Row 5 ErrorSummaryBox（现状已是可选中 TextBox，方案 B 追加复制按钮）。
数据通道：① 的「正在解压/已暂停/解压完成」现已有源（SetStatus/SetComplete）；② 的逐文件失败明细目前只有整操作异常 message —— 「video-04.mp4 解压失败，原因是没有写入权限」这类逐条明细需要新增数据通道（ArchiveProgress 目前只有 FailedFiles 计数 + EntryStatus 四态，无错误文本），此为该方案改动最大的一块。
本原型不含：状态行随语言切换刷新、复制内容是否含时间戳、多条错误的滚动/截断策略（后续设计再定）。
