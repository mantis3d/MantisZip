✓
参数区是宿主，不是硬编码：渲染层只遍历注册表生成「标签 + 控件」， 不认识 preserveFullPath 或任何具体 key。 将来别的调用情形要加参数、或参数要支持 ComboBox/TextBox 等类型，只扩展注册项的工厂，不动布局与容器。
上方控制台可验证：切「调用情形」看不同情形注册不同参数； 点「＋ 添加示例参数」看多参数自动换行；切「选择文件夹（无参数）」看整区隐藏。

计划审阅发现的问题（7 项，2 项阻塞实施）
D1 阻塞 初始勾选态从未回填到 CheckBox —— 计划 §3.4 只说「构造函数订阅事件」，XAML 也没有 IsChecked 绑定；spec §5.1 明确要求的「勾选态 = 初值」被整个丢掉。
后果：_extractPreserveFullPath 保留设置值，但复选框永远显示未勾选。 设置为 true 时，用户看到一个未勾选的框却得到保留路径的落盘结果 —— 视觉与实际背离。
修法：ExtractFolder 分支内先 PreserveFullPathCheck.IsChecked = _extractPreserveFullPath; 再订阅 IsCheckedChanged（反序会触发一次处理器回灌）。
上方「对照模式 → 计划原文（缺陷）」可直接复现此现象。
D2 阻塞 Picker_ExtractPreviewTitle 已存在，重复添加会破坏本地化加载 —— 计划 §5 把它列为 「新增 key」，但它已存在于三语文件第 1060 行。按计划再插到文件头会产生重复 JSON key， JsonSerializer 反序列化 Dictionary<string,string> 时对重复键抛 ArgumentException —— 整个本地化表加载失败，波及全应用文案。
修法：§5 只保留 Picker_PreserveFullPath 与 Picker_PreserveFullPathDisabledHint 两个新 key。
D3 禁用态 CheckBox 的 ToolTip 可能永不显示（直击决策 a 的目的） —— 计划与 spec 都写「Tooltip 常驻绑定即可，禁用时自然显示」。 但 Avalonia 中 IsEnabled=false 的控件不参与命中测试，ToolTip 依赖 pointer-over 事件， 因此提示很可能弹不出来。这会让用户只看到一个死复选框而无任何解释 —— 正是决策 a 想避免的备选 c「会被误判为功能损坏」。
修正后已解决：参数移出预览面板后，参数项渲染为 CheckBox + 独立可命中的 ? 触发器兄弟节点，禁用时提示挂在 ? 上， 不依赖禁用控件自身收事件。
D4 架构守卫测试无法定位源文件，且断言字符串对空白敏感 → 假通过 —— ExtractPreserveFullPathWiringTests 需在运行时读取 MainWindowViewModel.cs / DragDropService.cs，但测试项目没有任何源码定位设施（csproj 无 None Include 拷贝，代码里无 File.ReadAllText、无仓库根发现逻辑）。
更严重的是断言形如 不含 "settings.ExtractPreserveFullPath, settings.FileConflictAction"： 只要有人把该调用换行格式化，字符串消失，测试通过但缺陷仍在 —— 比没有测试更危险（虚假信心）。
修法：① 写仓库根发现（从 AppContext.BaseDirectory 上溯找 MantisZip.sln）； ② 断言前先归一化空白（Regex.Replace(src, @"\s+", " ")）；③ 更稳妥的是用花括号配平 截出 ExtractSelectedEntriesCoreAsync 方法体，断言其中完全不出现 settings.ExtractPreserveFullPath。
D5 ExtractPanelTitleText 与既有 ExtractPreviewTitle 重复 —— 对话框 code-behind 已有 ExtractPreviewTitle => T("Picker_ExtractPreviewTitle")（:112）。 计划 §3.4 又新增一个取值完全相同的属性，而 §3.3 的 XAML 注释说「保留原有 Text 绑定」、 代码块却绑 ExtractPanelTitleText —— 自相矛盾，会留下一个无人使用的死属性。二选一即可。
D6 两个消费点对空值处理不一致 —— §3.5 给 ExtractSelectedTo 写了 if (pick is null || string.IsNullOrEmpty(pick.DestPath)) return;， 给 DragDropService 却没写。且 §3.2 的返回判断 dialog.SelectedPath is { } path 对空字符串也会命中（Ok_Click 无条件 SelectedPath = _currentDir），理论上可能返回 ExtractPickResult("", ...)。
修法：返回判断改 !string.IsNullOrEmpty(path)，两处消费点统一守卫。
D7 DoD 丢失规则 3 的进度文档步骤 + 契约测试未指定 [AvaloniaFact] —— spec §12 最后一条要求更新 docs/PROGRESS.md 与 docs/progress-avalonia-detail.md， 计划 §7 的 DoD（作为上位文档）把它整条丢了。 另外 SelectedItemsExtractService 内部调用 AppSettings.Load() 与 LocalizationManager.T()，契约测试需按 MainWindowViewModelCommentTests 的先例用 [AvaloniaFact]，并隔离 %LOCALAPPDATA%\MantisZip\settings.json 以免读写开发者真实设置。
已核实无误 全部行号（:79 / :136-139 / :2333 / :2354 / :2365 / :2375 / DragDropService :75/:84/:105）逐条比对准确； MainWindow.axaml.cs:183-184 表达式体 lambda 确实零改动； §4.1 三条「mock 不可写」理由全部成立（已核实 DragDropService 为 internal class、 InternalsVisibleTo 仅授予 MantisZip.Tests）； 决策 a 的等价性由 TrimCurrentFolderPrefix 源码证实； 测试基线 105 通过 / 2 跳过 实测一致，§7 的 111 算术正确； 规则 1 已合规（docs/PLAN.md:37 已有 P2 条目）。
