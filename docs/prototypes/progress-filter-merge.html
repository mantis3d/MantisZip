为什么是替换而不是并存

统计卡不表示「可点」，胶囊天然表示。同一串数字既当统计又当入口， 用户会先把它当读数、把胶囊当按钮 —— 这正是 issue #81 说的「信息冗余」。 切到「合并前」对比按钮能直接看到：旧版要多占一整行。

十张卡走掉六张，去哪了

卡去处
压缩包 1/1Row 0 批处理区表头已有 BatchCountText（进度窗.axaml:78）
总大小 41.76 MB底部合并行右侧（本原型已放 31% · 已用 · 剩余 那一行）
已处理 742底部合并行左侧 📥 24.9 MB 旁边可加；或干脆不显（百分比已表达）
扫描 / 暂存 / 压缩后 / 仅存储列表档看逐条目时不看引擎内部计数；切回完整档就有

留下的四张（跳过 / 出错 / 已覆盖 / 已完成）恰好都是有「异常语义」的 —— 也就是用户真的会想点进去看的。

三个必须一起解决的点

① 已完成的计数没有 —— _statsProcessed 是 p.ProcessedFiles， 语义上包含跳过和出错，不能直接当「已完成」。要么在 UpdateEntryStatus 里加 _entryCompletedCount 累加，要么从 _entryItems 现算（5000 条 <1 ms）。本原型已用 * 标注。

② 列表档的「已处理」消失 —— 十卡里「已处理 742 / 24.9 MB」是唯一能看出「做了多少」的量， 挪到底部合并行左侧（本原型 📥 24.9 MB 那个位置）。

③ 切档时整行换内容 —— 两个形态都是 22px 一行、同样的圆角与底色， 切换只换子里面的东西，视觉上不会「页面跳一下」。真机上要验证这一点。

实现要点

点做法
XAML 结构 StatsCardsPanel（ProgressWindow.axaml:701-705）现在整块绑 IsVisible="{Binding IsFullDensity}"。 改成外层一个 Border 常驻、里面两套内容：StatsCardsPanel 绑 IsDetailedOrFull， 新的 EntryFilterBar 绑 IsListMode。两个都要能同高，否则切档会跳。
过滤数据源 不动 _entryItems（ActivateEntryByName 还按 Name 全表匹配）， 另开 EntryViewItems 投影集合。不能用 ICollectionView —— Avalonia 12 主包没有。
过滤时机 切过滤器全量算一次 + UpdateEntryStatus / ActivateEntryByName 里 State 变了单行增删。只认 State —— Percent 每帧都变。
已完成计数 新增 _entryCompletedCount（在 UpdateEntryStatus 里从非终态转 Completed 时 +1）， 或从 EntryItems 现算 —— 前者 O(1) 但要小心重复计数，后者简单但每次切换都遍历。
空状态 过滤后 0 条 → 「没有匹配的条目 + 显示全部」。现在没有这块，必须新增。
徽标数字 StatsSkippedCount / StatsFailedCount / StatsOverwrittenCount 已存在（ProgressViewModel.cs:851-857），直接绑。总数用 EntryItems.Count。
5000 条上限 软肋：MaxSeedEntryCount = 5000 是「超了就不建行」（CompressFlow.cs:377 / ExtractFlow.cs:426）。 超大包列表本来就是空的，过滤器无从谈起 —— 要不要放宽需单独决策。

这一版没做的

① 极简 / 标准两档 —— 它们的 Row 3 没有卡片行，也不该有过滤条（没有列表可过滤），保持原样。
② 5000 条上限放宽 —— 与过滤器是两件事，需要先决定「超限时要不要退化成只播异常项」。
③ 切档动效 —— 先确认「同高不跳」够不够，不够再加淡入。
